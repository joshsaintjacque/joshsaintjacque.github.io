# Throw More Code Away

You should throw away more of the code you write. This has always been true. We start down one path only to realize once we're knee deep in it that another approach would have been better. But now you have to make a decision. Do you throw away all your work and start over, or continue down the path you're on? Sometimes you're under a time crunch and continuing is the more pragmatic option. Other times you're just emotionally invested in what you started on. It may not feel good to "waste" the time you spent writing the code, so you might choose to keep the inferior approach anyway.

There's always been maturity in throwing away that code. Setting aside ego and sunk cost fallacy and doing what's best for the team and the project instead.

Now it's much easier to make the right choice. [[On Orchestration|AI is fundamentally changing how we build software]], and one side-effect of those changes is that writing code is now the cheap part. You can throw away code without worry since writing the new solution can be done quickly. Because of this your threshold for discarding code should be very low. The process of building software is one of discovery: the learning you do in the process is the valuable part. Take the learning, delete the code.
